# detour_analyzer: agent index

Read this first; open source files only for the function you need to change. README.md (Spanish) has the user-facing docs and result tables.

**Goal:** forecast monthly consumption of paper SKUs per planta from SAP exports, aggregated bottom-up to planta and total.
**Rules:** chronological splits and rolling origin only (never random). Code and comments in English. Scripts in `scripts/` are thin CLIs (`sys.path.insert` + argparse); logic goes in `src/engine/` (produces the forecast), `src/evaluation/` (backtests, metrics, tuning, planner and internal comparisons; imports engine) or `src/experiments/` (ideas under test; imports both), one responsibility per module. Imports only go engine <- evaluation <- experiments <- app (`tests/test_layers.py`; `src/app/` is the desktop app). Run from the repo root.
**Metrics:** WAPE = sum|y-p| / sum y; accuracy = 1 - WAPE; bias_pct > 0 means under-forecast.
**Env:** `python` is not on PATH in the Bash tool (Windows Store alias); use PowerShell or locate the interpreter.
**Dependencies:** pinned direct dependencies split in `requirements/base.txt` (production), `evaluation.txt`, `app.txt`, `dev.txt`; `requirements.txt` installs everything. Python 3.11 or 3.12. CI (`.github/workflows/tests.yml`): Linux and Windows x Python 3.11 and 3.12, runs `pytest` under `coverage` on every push and fails if src/ coverage drops below 90%. Verified in fresh venvs: base alone reproduces `results/forecast_2026-10.csv` byte for byte; dev passes the whole suite.
**Do not:** reintroduce neural nets (removed as too heavy, c2e3330); edit files when the user pastes a code chunk, answer with the corrected chunk in chat.

## Data
`data/consumos_long.csv` (master): `planta, sku, fecha, consumo`; 347,502 rows, 15 plantas, 2024-01-02..2026-09-30 (33 months, last complete month 2026-09). `sku` = material description. Negatives clipped to 0. Built from `consumos_2024_2025.xlsx` + `consumos_2025_10_2026_09.xlsx` (both long) with `--drop-zeros`; the two overlap in 2025-10..12 with identical values, `combine_exports` keeps them once and stops only if values differ. `consumos_2026.xlsx` (wide, to 2026-06) and `consumos_2024_ene.xlsx` are superseded and no longer in the repo's flow.
Planner forecasts: `data/planner_forecast_<YYYY-MM>.csv` (`planta, mes, sku_planner, product_sap, strategy, forecast_to` in TO), 11 plantas (SALI, SALM, SQUA, SBUR, SPAL, SCOC, PCEL, SCVA, SALC, SCAN, SVIG), months 2026-06, 2026-07, 2026-08, 2026-09, written by `transform_planner.py` from the monthly assignment workbooks (one sheet each; `Customer` = planta; the `allocation` column is the producing mill and is dropped). Strategies: VMI, NO VMI, VMI EST (24 rows), a few empty. `sku_planner` is `grade/subgrade/gsm/width` without core width. SCAN rows of 06..08 equal the previous files; SCAN 2026-09 has 45 SKUs (the old file had 32: the 13 missing were NO VMI).

## Core objects
- `Panel` (panel_utils): arrays series x month: `monthly` (NaN before first appearance), `active_days`, `daily` (zero-filled), `planta_monthly`, `total_monthly`, `business_days` (no Sundays), `labels`, `first_month`, `planta_code`. Built by `build_panel(load_consumption(csv))`. Window helpers: `window_mean/std/rate`.
- `make_frame(S, horizon)` (feature_utils): one row per (origin `o`, series alive); target month `t = o + h`; columns `series, o, t, planta_code, y`, the 25 `SERIES_FEATURES`, and baseline forecasts `p_<name>` (`BASELINES`). All windows end at the origin: no leakage. `direct_forecasts` applies the simple models to an aggregated series.
- `fit_predict_trees(kind, params, train, test, seed)` (tree_utils): `kind` in lgbm / xgb / rf; LGBM/XGB use Tweedie with early stopping on the last 2 target months; `TREE_BASE` holds the pre-tuning params.
- `reconcile` (evaluation_utils): rescales SKU forecasts to the direct planta `mean6_x_seasonal`. `score_models_by_level` ranks models at sku/planta/total.
- Tuning: `make_folds` (3 walk-forward folds x 3 months), `run_study` (TPE, baseline enqueued as trial 0), `compare_base_and_tuned` (h=1 and h=3 on the test months), `to_jsonable`.
- Ensembles: `ENSEMBLE_GROUPS` = ml (lgbm, xgb, rf) only; `SIMPLE_MODELS` = naive (reference outside the ensemble). The 9 classical models (mean3/6/12, perday6, seasonal_naive, mean6_x_planta, ses, damped_holt, arima), their ensembles econ / ml_econ and `econometric_utils.py` (and `statsmodels`) were removed. `METHODS` = mean, median, trimmed (20%), weighted (1/past MAE, only months <= t-h). 8 models total (lgbm, xgb, rf, naive, ml_mean/median/trimmed/weighted). `model_confidence_set(loss, period, block, n_boot)` = Hansen-Lunde-Nason, block bootstrap over months.

## Guards and tests
- `data_checks` (engine): `load_consumption(path, validate=True)` runs `validate_consumption` on every load. Errors stop (`InputValidationError`, a SystemExit): columns, types, missing, negative, duplicate, keys, near_duplicate_keys, month_gap, day_gap, last_month (only with `require_complete_last_month`). Warnings print the rows and go on: daily_peak (> 100 TO), spike (> 20x the series median), rows_drop, planta_set, sku_format. Sunday rows count as real consumption. Never corrects data. `validate=False` is the explicit escape hatch.
- `fingerprints` (engine): `panel_fingerprint`, `params_hash`, `file_sha256` (cache_utils re-exports the first two).
- `cache_utils`: `panel_fingerprint` (hash of series, months and values, independent of line endings), `expected_meta`/`check_meta` (the cache `results/member_forecasts.meta.json` must match data, horizon, test window and tuned params, else stop with "--refit"), `check_alignment` (the series index stored in a cache must reproduce the panel's actuals).
- The series index is the position in the alphabetical (planta, sku) list (`Panel.keys`); adding one SKU to the master shifts it, so a stale cache is rejected instead of silently misread.
- `tuning_utils.tuning_meta` is saved as `meta` inside each model of `results/tuning_trees.json` (windows, folds, data hash); `check_tuning_window` rejects tuned parameters whose tuning window reaches the test months (leak); `run_study` refuses to resume an Optuna `--storage` study fitted to other data.
- Tracking guards (`tracking_utils`, `tracking_service`): a forecast with fewer than half of its series in the loaded data (`coverage_ok`, `MIN_COVERAGE`) is not offered for measuring and `measure` / `track_saved_forecast` refuse it before storing anything; a ratio with no real consumption is NaN, never `inf`; `tracking_rows` refuses infinite values and `read_tracking_csv` reads them as empty, so a bad history file cannot break Inicio or Seguimiento. `tests/test_tracking.py` also checks that no forecast made by a test (manifest path in a pytest temp folder) is committed in `results/`. Origin of the guard: a test forecast of 2025-07 (planta "A", SKU0..) was committed in `results/` and measuring it wrote `-inf` into `seguimiento.csv`.
- Tests: `python -m pytest -q` (synthetic data, 2 min 10 s on the Windows PC, 292 tests, 97% coverage of src/ (measured 2026-10-20); `tests/test_inference.py` checks that the future-month features equal the rolling ones): no leakage in features, panel and daily sums, ensemble weights use only known months, reconcile totals, metric sign, tuning folds, cache and tuning guards, transform overlap rules, planner SKU matching, tree determinism, MCS. The suite was checked by mutation: 8 injected bugs were all caught.
